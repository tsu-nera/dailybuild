# 習慣レビュー（週次）

入力は Habitica（本人がタップ）、正本は `data/habitica/history.csv`、対象と目標値は
`config/habits.yaml`。このスキルは読み手を担当する。

**週次でのみ回す。** 出力はすべて週を単位にした量で、1日に切ると読めるものが
残らない。Habit の 0 を未実行と読めない以上、日次では書ける文が存在しない。

`/weekly-review` とは別に回す（あちらは体組成・睡眠・メンタルのレポート）。

## Step 1: 取得と集計

```bash
cd /home/tsu-nera/repo/dailybuild
uv run scripts/habitica.py fetch
uv run scripts/habitica.py show --weeks 4
```

`--weeks` は既定4。長期の傾向を見るときだけ増やすか、`--unit month --months 3`
に切り替える。**達成率を判定に使うなら28日を下限にする**（7日窓では達成率が
14pp 刻みでしか動かず、90% のような閾値が「1回でも落としたか」に潰れる）。

`show` が非ゼロで終わったら、`config/habits.yaml` が対象に指定した習慣が
Habitica から消えている（リネームか削除）。**直すまでその習慣はレビューされない。**

## Step 2: レビュー

出力を読んで所見を述べる。**`show` は表しか出さない。**読み方はここにしか無い
（両方に置くと片方だけ更新されて漂流する）。**言わないことのほうが重要**なので先に書く。

### 言わない

- **Habit の行（回数・最後に記録された日）を評価に使わない。** 押し忘れと未実行が
  区別できず、分母も原理的に無い。習慣は Daily に寄せる方針で、Habit が残っている
  間の暫定表示
- **cron が走らなかった日を未達に数えない。** 「記録の被覆」が分母で、そこに
  無い日は欠測。被覆が低い週は Daily の達成率そのものに触れない
- **`(途中)` の付いた週を、完了した週と比べない。** 経過日数ぶんしか無いので、
  被覆も回数も必ず小さく出る。前週比はその1つ手前の週まで
- **連続日数（streak）を出さない。** 押し忘れ1回で折れるので、測れないものを
  指標にすることになる
- **`target_per_week` が空のうちは達成／未達を判定しない。** 目標が無い習慣に
  勝手な基準を当てない

### 言う

- 週ごとの回数と、前週からの変化
- 目標がある習慣は「目標に対して何回」（4週の平均で見る。単週で判定しない）
- 達成率（4週の平均で見る。被覆が低い週の達成率には触れない）
- 時刻の変動性（dayStart 5時起点の経過分。離床時刻の分散と同じ土俵で読む。
  回数が横ばいでも変動性が下がっていれば前進）
- IRT の中央値と最大（最大は空白の長さ。ただし cron 欠測を含むので、行動の
  空白と決めつけない）
- 卒業候補。**`show` は出さないので value を自分で見る**（既定は 5 以上が目安）:

  ```bash
  jq -r '(.habits[],.dailys[]) | [.text, (.value|tostring)] | @tsv' data/habitica/tasks.json
  ```

  **Tag を付けるのは本人**で、agent は外さない。`track: down` の習慣は候補に
  しない（value が「押していない期間」で上がるだけで、押し忘れと区別できない。
  up/down 両方が立つ Habit は放置しても減衰しないので、一度候補に出すと再発時
  にしか外れない）。減らす習慣の卒業は本人の申告による

## Step 3: 対象の出し入れ

`config/habits.yaml` の `habits` に書いたもの**だけ**をレビューする。Habit と
Daily を区別せず名前で指定する。書いていないものは `show` に出ない（Habitica
からは消さない）。何が対象外かは yaml と Habitica を突き合わせて確認する。

`track` は Habit のときだけ書く（`up` / `down`）。**Habitica の up/down フラグ
ではなくこちらが正。** Daily には向きが無いので書かない。

**Habitica の Daily は「週x回」を表現できない**（`frequency` は曜日か `everyX`
のみ）。repeat を全曜日にして毎日 due にし、週何回かは `target_per_week` で持つ。
曜日固定にすると動けない日に未達が確定して融通が利かない。代わりに、目標が週7未満
の Daily は**目標日数を超えた分だけ毎週 HP を削られる**。difficulty を Trivial に
落とすと軽くできる（`docs/habitica.md` のとおり、agent は提案だけで変更しない）。

対象を増やしたい／減らしたいという話が出たら、実測を根拠にする。全期間の押下日と
最終押下日は history.csv から出る:

```bash
awk -F, 'NR>1 && $4=="habit" && ($9+0>0 || $10+0>0){print $1,$5}' data/habitica/history.csv
```

## Step 4: 目標値の見直し

`target_per_week` は本人が決める。**agent が実測から勝手に埋めない。**

4週ぶんの記録がそろってから、目標と実績が離れている習慣があれば提示する。
上げるか下げるか続けるかは本人が決め、合意が取れたら yaml を書き換える。

変更は git に残るので、いつ何から何へ変えたかが履歴になる。

## Step 5: 卒業と復帰

卒業させるときの Habitica 側の操作は2つ。**両方やる。**

1. `repeat` を全曜日 `false` にする（due にならなくなる）
2. Tag「卒業」を付ける

2 を忘れると「なぜ due でないのか」が後から分からない。除外の条件は Tag だけで、
`value` は候補の提示にしか使わない（value が高いだけで黙って外すと気づけない）。

**卒業すると `value` が凍結するので、自動での復帰判定は働かない。** 崩れたことは
機械では検出できない。戻すのは本人の申告による。
