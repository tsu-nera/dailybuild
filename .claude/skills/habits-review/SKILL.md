# 習慣レビュー（週次）

入力は Habitica（本人がタップ）、正本は `data/habitica/history.csv`、目標値は
`config/habits.yaml`。このスキルは読み手を担当する。

`/weekly-review` とは別に回す（あちらは体組成・睡眠・メンタルのレポート）。

## Step 1: 取得と集計

```bash
cd /home/tsu-nera/repo/dailybuild
uv run scripts/habitica.py fetch
uv run scripts/habitica.py show --weeks 4
```

`--weeks` は既定4。長期の傾向を見るときだけ増やす。

## Step 2: レビュー

出力を読んで所見を述べる。**言わないことのほうが重要**なので先に書く。

### 言わない

- **Habit の 0 を「やらなかった」と読まない。** 押し忘れと未実行が区別できない。
  「今週0回でした」を未達として扱わない。一度も押していない習慣も 0 行で出るので、
  「登録したが未着手」と「やめた」の区別もつかない
- **「減らす」の表を評価に使わない。** down Habit は押し忘れで過少に出るうえ、
  機械で裏が取れない。参考として出しているだけ
- **cron が走らなかった日を未達に数えない。** 「記録の被覆」が分母で、そこに
  無い日は欠測。被覆が低い週は Daily の達成率そのものに触れない
- **連続日数（streak）を出さない。** 押し忘れ1回で折れるので、測れないものを
  指標にすることになる
- **`target_per_week` が空のうちは達成／未達を判定しない。** 週何回できるかの
  実測が無い段階の目標は推測でしかない

### 言う

- 週ごとの回数と、前週からの変化
- 目標がある習慣は「目標に対して何回」（4週の平均で見る。単週で判定しない）
- 卒業候補が出ていれば提示する。**Tag を付けるのは本人**で、agent は外さない

## Step 3: 目標値の設定（4週たまってから）

`config/habits.yaml` の `target_per_week` が空で、その習慣の記録が4週ぶん
そろっていたら、実測の中央値を基準に値を提案する。合意が取れたら yaml を書き換える。

変更は git に残るので、いつ何から何へ変えたかが履歴になる。

## Step 4: 卒業と復帰

卒業させるときの Habitica 側の操作は2つ。**両方やる。**

1. `repeat` を全曜日 `false` にする（due にならなくなる）
2. Tag「卒業」を付ける

2 を忘れると「なぜ due でないのか」が後から分からない。除外の条件は Tag だけで、
`value` は候補の提示にしか使わない（value が高いだけで黙って外すと気づけない）。

**卒業すると `value` が凍結するので、自動での復帰判定は働かない。** 崩れたことは
機械では検出できない。戻すのは本人の申告による。
