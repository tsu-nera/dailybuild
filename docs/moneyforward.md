# MoneyForward ME

公式 API が無いため、Playwright で保持したログインセッションを使って
`/cf/csv`（収入・支出詳細のダウンロード用エンドポイント）を月単位で、
`/bs/history/csv`（資産推移）を1本叩く。CSV の無い口座別残高だけは `/bs/portfolio` と
`/bs/liability` の画面を開いて表を読む（下の「口座別残高」）。
ハマりどころ:

- レスポンスは `charset=utf-8` を名乗るが実体は **cp932**
- User-Agent に `HeadlessChrome` が入っていると **403**。通常の Chrome に偽装する
- セッションが切れると 200 のままログイン画面 HTML が返る。CSV ヘッダで検証して
  落としているので、欠測を捏造せずエラー終了する（`--login` で取り直す）
- 明細は MF 側で後から分類・金額を変更されることがある。マージは `ID` 基準の
  上書きなので取り直せば追従するが、MF 側で削除された明細は CSV に残り続ける
- セッション切れで日次実行全体を止めないよう、`daily-fetch.sh` は
  ステップ単位で失敗を握って続行する

CSV に出るのは **MF が金融機関から取り込み済みの明細だけ**。自動更新は1日1回
程度しか走らないため、叩くだけでは数日古いままになる。`--refresh` は画面の
「金融機関からのデータ一括更新」と同じ `POST /faggregation_queue2` を叩く。

更新は金融機関ごとに非同期で走り、**カード会社は完了まで10分以上かかる**
（実測: 楽天カードはキックから8分経っても「更新中」）。同期的に待つのは
現実的でないため完了は待たず、キックの結果は**次回の取得で回収する**。
日次で回している限り、明細は実質1日遅れで揃う。

「設定エラー」「要ワンタイムパスワード」等になった連携は一括更新では復旧せず、
その口座の明細は CSV から丸ごと欠ける。黙って欠測しないよう、取得のたびに
正常でない口座を警告する（再認証は MF の画面で手作業）。

MF の明細は **2015-02 まで遡って取得できる**（閲覧期間の制限は無い。2015-01 以前は
0 件 = MF 側に記録が無い）。`--unit year` の既定期間はこの最古年から当月までで、
`EARLIEST_YEAR` に持たせてある。ただし連携が壊れている口座の明細は過去分も丸ごと
欠けるため、古い年ほど支出は過少に出る。

`mf.py show` は `計算対象=1` の明細だけを集計する。口座間の振替は MF 側で必ず
`計算対象=0` が付くのでこの絞り込みだけで落ちる。MF は引き落とし予定日の
**未来明細**を含むため、「直近Nヶ月」は当月末で上限を切っている。

## 資産推移（`/bs/history/csv`）

`日付, 合計（円）, 預金・現金（円）, 投資信託（円）, …` の CSV が返る。内訳の列は
保有状況で増減するのでコードに列名を持たせない。明細と同じく 2015-04 まで遡れる。

- **期間を絞るパラメータは無い**。`range` / `from`+`to` / `year` はいずれも無視され、
  常に全期間が返る（`from`+`to` を付けると 0 件になる）
- **粒度は当月だけ日次、前月以前は月末1点**。月をまたぐとその月の日次は
  MF 側から**二度と取れない**。`fetch` が明細と一緒に毎回取っているのはこのため
  （マージは日付キーの置換なので、既に取った日次の行は消えない）
- 合計に**負債は入らない**（総資産であって純資産ではない）。負債は `/bs/liability`
  の HTML のみで、`/bs/liability/csv` は 404
- 口座別・銘柄別の内訳は CSV に無い。`/bs/portfolio` の HTML にあるが現在値だけで
  履歴が無いので、毎日の取得で現在値を積んで自前で履歴を作る（次節）
- 連携が切れている口座の残高はここでも丸ごと欠ける（資産額は構造的に過少）

## 口座別残高（`/bs/portfolio`・`/bs/liability` → `data/mf/balances.csv`）

`fetch` が明細・資産推移と同じセッションで2ページを開き、表を読む（読むのは `src/lib/mf/balances.py`、
保存は `src/lib/mf/store.py` の `save_balances`）。MF 側に履歴が無いので、**取らなかった日の値は二度と取れない**。

- `/bs/portfolio`: 見出し「預金・現金」「投資信託」「暗号資産」「ポイント」ごとに表がある。種類は**表の直前の見出し**で決め、
  列は見出し（th）の文字列で引く（表の順番・列の位置に依存しない）。`保有金融機関` 列の無い表（ページ末尾の
  日付選択のカレンダー、先頭の集計表）は読まない。持っていない種類（株式・年金等）は見出しごと出ない。
  4種類以外の見出しの下に口座の表が出たら警告して読み飛ばす
- `/bs/liability`: `種類 | 名称・説明 | 残高 | 保有金融機関` の表。値は**カードの「ご利用残高」で、次回の請求額ではない**。
  同じ金融機関・同じ名称の行が複数ある（楽天カード2枚がどちらも `ご利用残高`）ので、キーに出現順の `seq` を持つ
- 取得・保存に失敗しても警告を出して続け、明細・資産推移の取得と保存は止めない

列は `date, kind, institution, name, seq, status, value, quantity, unrealized_gain, category, expires`。

| 列 | 中身 |
|---|---|
| `date` | 取得した日（JST の暦日） |
| `kind` | `預金・現金` / `投資信託` / `暗号資産` / `ポイント` / `負債` |
| `institution` `name` `seq` | キー。保有金融機関・名称（銘柄名）・同じ2つの中での出現順（1始まり） |
| `value` | 円換算の金額（投資信託は評価額、ポイントは現在の価値、負債は利用残高） |
| `quantity` | 投資信託の保有数・ポイント数 |
| `unrealized_gain` | 投資信託の評価損益 |
| `category` | 負債の `種類`（クレジットカード利用残高 等）・ポイントの `種類` |
| `expires` | ポイントの有効期限（画面の文字列のまま） |

**キーごとに、今日より前の直近の状態から変わった行だけを書く**（`status` と金額・付帯の欄を比べる）。
`status` は3状態:

| status | 意味 | 日次に戻すとき |
|---|---|---|
| `ok` | 通常 | 次の行まで値を引き継ぐ |
| `missing` | 金額が `–円`・空（0にしない）。直前も missing なら書かない | そのキーを合計から外し、欠測の件数に数える |
| `gone` | 前回まであったキーが、**取得できた**今回のページに無い。値は空 | 以後は引き継がない。再び現れたら `ok` の行が出る |

- 同じ日に2回取ったら、その種類の今日の行を消してから今日より前の最新状態と比べ直す（二重に入らない）
- ページの取得・parse が失敗した／行が0件だったときは、そのページの範囲（portfolio なら資産の4種類、
  liability なら負債）の今日の行を消さず、gone も書かない（全キー一斉 gone の誤記録を防ぐ）
- 日次に戻すのは `src/lib/balances.py`（`dashboard.py build --only balances`）。取得が止まった日も直前の値を
  引き継いでしまう（変わらなかった日と見分けられない）ので、鮮度は取得ログで見る

## 定期契約の台帳（`mf.py contracts`）

実装は `src/lib/mf/contracts.py`。台帳の実体は `config/private/contracts.yaml`
（dailybuild-private。スキーマは `config/contracts.yaml.sample`）。

- **台帳が正本、MF の明細は照合だけ。** 固定費の月額を明細から出すと計上ズレで暴れ
  （#102）、年契約・2年契約は更新月にしか出ない。月割りは `amount / cycle_months` の合計
- 次回更新日は `anchor` から `k * cycle_months` ヶ月を**毎回 anchor から**足して求める。
  月末は月末に丸める（1/31 月次 → 2/28, 3/31, 4/30）。丸めた日から数え直すとドリフトする
- **通貨は換算しない。** 合計は通貨ごと・kind ごと。`ended` のある契約は日付に関わらず
  一覧・合計から外れる
- 照合は `内容` 列への部分一致（regex ではない）で、支出（金額 < 0）だけを見る。
  「請求が無い」は期待日が今日から10日以上前のものに限り、期待日 ±10 日で判定する。
  「台帳に無い繰り返し」は固定か変動かを判定しない（候補を人か agent が見て台帳に足す）
- 税・社会保険は契約ではないので台帳の対象外（積立として別に扱う）
- **保険は台帳が正本。** 証券番号・補償・連絡先・控除の種類は契約の `insurance` キーに
  持つ（型と検証は `src/lib/mf/insurance.py`）。別ファイルにしないのは name の同期が要るため。
  加入者番号が分からないと控除証明書を再発行してもらえず、控除を落とす。
  `policy_no` は引用符で囲む（数だと YAML が8進に読み先頭0が落ちるのでエラーにしてある）。
  証書は画像を dailybuild-private の `data/insurance/<契約名>/` に置き、細部の補償は書き写さない
- 一覧は `mf.py insurance`（MF の明細は読まないので認証なしで動く）。insurer・policy_no・contact
  の欠けた契約は「未記入」に出る。**確定申告では `mf.py insurance --deduction` から
  控除証明書を集める**
