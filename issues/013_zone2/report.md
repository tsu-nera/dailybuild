## 総括・考察（最終 / Opus 4.7）

> 本セクションは2回の改訂を経た最終版。撤回した過去主張を明示しておく:
> - 初版「新ロジックは総分数が大幅に多い」← 0.37倍と矛盾。**撤回**
> - 第2版「Tanaka推定は+15bpm過大、③は不適切」← 観測最大166は"追い込んでいない"ことの帰結であり真の最大HRではない。較正データが原理的に存在しない以上、過大/過小は**判定不能**。**撤回**

### 結論サマリー

| 観点 | 評価 |
| --- | --- |
| データ・実装・手法 | ✅ **問題なし**（手法=カルボーネン%HRR、実装=正常、データ=妥当） |
| Tanaka maxHR 採用 | ⚠️ **未較正だが合理的な暫定値**。実測データが無い以上ベストな判断。「不適切」ではない |
| 旧 vs 新の総量差（3633→1354, 0.37倍） | 仕様通り。基準（%HRmax vs %HRR）が違うだけで欠陥ではない |
| Z5=0 / Z4=16分 | **欠陥ではなく使い方の特性**。全力運動の習慣が無いため上位ゾーンは「測れない」のでなく「使っていない」 |

### 評価1: アルゴリズム3層は健全

| 層 | 評価 | 根拠 |
| --- | --- | --- |
| ① カルボーネン%HRR手法 | ✅ 適切 | %HRmaxより上位の標準手法。安静時HRを考慮し個人適合性が高い |
| ② 実装（`hr_zones.py`） | ✅ 正しい | HRR算出・閾値適用・単調増加assert すべて正常。バグなし |
| ③ 入力 maxHR（Tanaka推定） | ⚠️ 未較正の暫定値 | 近年 最大HRまで追い込んだ実測が無いため Tanaka を暫定採用。これは合理的判断。観測最大166も追い込み不足の結果であり真の最大ではない → 過大/過小は判定不能 |

### 評価2: 旧 3633分 → 新 1354分（0.37倍）の正体は「低強度の切り落とし」

総量減少は新ロジックが厳しいからではなく **集計下限の定義差**:

- 旧 Fitbit fat_burn 下限 ≒ %HRmax 50%（≒90〜100bpm）と低い
- 新 Z1 下限 = %HRR 50% = **115.5 bpm**（RHR50を差し引くカルボーネン法の帰結）
- → 95〜115bpm帯（全分の95%ileが96bpm）が旧ではfat_burn計上、新では**ゾーン外**

「軽い活動を訓練として数えるか」のポリシー差。新ロジックは「真に有酸素刺激のある運動」のみ拾う設計で生理学的により誠実。旧3633分は運動量を過大に見せていた。

### 評価3: 上位ゾーンが空なのは正常な出力

| 指標 | 値 |
| --- | --- |
| 観測最大HR（90日 intraday 101,634分） | 166 bpm |
| 日別最大HRの中央値 | 126 bpm |
| 新 Z5 下限 / Z4 下限 | 167.9 / 154.8 bpm |

%HRR 90%（Z5）は「ほぼ全力」相当。インターバル走等をしなければ空なのは当然。
Z5=0 は較正バグではなく**運動習慣の正直な反映**。

### 評価4: 実用上の朗報 — 常用帯は maxHR 誤差に頑健

ゾーン下限の maxHR 感度（カルボーネン式の偏微分）:

| ゾーン | maxHR 1bpm変化あたりの境界変化 | 仮に maxHR±15bpm のときのブレ |
| --- | ---: | ---: |
| Z1 下限 | 0.50 bpm | ±7.5 bpm |
| Z5 下限 | 0.90 bpm | ±13.5 bpm |

RHR=50（実測・良好）が下端を固定するため、**低強度帯ほど maxHR 不確実性に頑健**。
実際に過ごす Z1〜Z2 域は、空の Z5 が示唆するほど壊れていない。

### 二次的な注意点

1. **データソース差**: 旧=Fitbit AZM API（76日）、新=intraday自前集計（85日）。母数9日差が総量比較に誤差を乗せる
2. **RHR=50bpm**: 直近30日中央値。良好かつ妥当。境界算出への影響は適切
3. **AZM単位**: 本データの activeZoneMinutes は fat_burn+cardio+peak の単純和（Fitbitの cardio/peak 2倍重み付け無し）と確認済み。分単位で直接比較可能
