# 習慣レビュー（週次）

入力は Habitica（本人がタップ）、正本は `data/habitica/history.csv`、対象と目標値は
`config/private/habits.yaml`。このスキルは読み手を担当する。

**設計の定義は [docs/habits.md](../../../docs/habits.md)**（段・移行条件・達成率の分母・意図的に持たないもの）。ここには手順だけを書く。

**週次でのみ回す。** 出力はすべて週を単位にした量で、1日に切ると読めるものが
残らない。Habit の 0 を未実行と読めない以上、日次では書ける文が存在しない。

`/weekly-review` とは別に回す（あちらは体組成・睡眠・メンタルのレポート）。

## Step 1: 取得と集計

```bash
cd /home/tsu-nera/repo/dailybuild
uv run scripts/habitica.py fetch
uv run scripts/habitica.py show --weeks 4
```

**`--weeks N` は進行中の週を含む。** 移行を判定するときは1つ多く取る
（4完了週なら `--weeks 5`、12完了週なら `--weeks 13`）。

`show` が非ゼロで終わったら、`config/private/habits.yaml` が対象に指定した習慣が
Habitica から消えている（リネームか削除）。**直すまでその習慣はレビューされない。**

## Step 2: レビュー

出力を読んで所見を述べる。**言わないことのほうが重要**なので先に書く。

### 言わない

- **Habit の 0 を「やらなかった」と読まない。** 押し忘れと未実行が区別できない。
  「今週0回でした」を未達として扱わない
- **「減らす」の表を評価に使わない。** down Habit は押し忘れで過少に出るうえ、
  機械で裏が取れない。参考として出しているだけ
- **`clear` の分子と分母の差を「やらなかった週」と読まない。** 分母は行があった
  完了期間で、分子はそのうち目標を満たした期間。**進行中の期間は入っていない**
- **週ごとの内訳は出ていない。** どの週が落ちたかは現在の出力からは分からない
  （表が横に伸びるので外した。見せ方は未決）
- **「最後に記録された日」を「N日やっていない」と読み替えない。** 記録について
  の文であって、行動についての文ではない
- **連続日数（streak）を出さない。** 押し忘れ1回で折れるので、測れないものを
  指標にすることになる
- **`target_per_week` が空のうちは達成／未達を判定しない。** 目標が無い習慣に
  勝手な基準を当てない

### 言う

- 窓のクリア数（`clear` 列 = クリアした完了期間 / **観測できた**完了期間）と、
  前回のレビューからの変化
- **`clear` の分母が移行条件の期間数に足りないうちは判定しない。** `2/2` は
  「2期間しか観測していない」であって条件を満たした意味ではない
- 「最後に記録された日」が窓（既定4週）より古い習慣は、そこを指摘する。
  4週の表では `-` が並ぶだけで空白の長さが見えない
- IRT（実施した日の間隔）は出ていれば読む。実施が1日しか無いうちは `-` で、これは正常。
  **段の判定には使わない**（間隔の規則性であって自動性ではない）。週4目標を週末に
  まとめているのか散らしているのかが見えるので、介入の材料にはなる

### MO（動機づけ操作）を見るとき

参照は `reports/metrics_daily.csv` 1本（日付 index。睡眠・HRV・RHR に加え、朝夜
フォームの気分／身体／頭／満足感／達成感が入っている）。**MO のために新しい記録は
取らない。**

**複数の習慣が同時に落ちているときだけ見る。** 単一の習慣の低下は行動固有の問題
（強化子の飽和、文脈の変化）で、MO を見ても当て所を外す。同時低下のときだけ
「個別の習慣ではなく MO の問題」として扱い、介入は `targets` を空で立てる。

- **単日の逸脱を MO で説明しない。** この記録では急性の体調イベントがほぼ発生しない
  ので、1日の落ち込みに MO を当てるとほぼ後付けになる。週単位で、複数習慣が揃って
  動いたときだけ
- **HRV / RHR から気分を読まない。** 気分との相関は実測で null
- **条件別の生起率比較（睡眠6h未満/以上で実行率が違うか）はまだやらない。**
  `habits_daily.csv` の行が溜まるまで n が無い。join 1回で書けるが、書いても入力が空

## Step 3: 介入

台帳は `reports/habits/INTERVENTIONS.md`。書式と、1ファイルにしてある理由は
ファイル冒頭にある。

**新しい介入を提案する前に台帳を読み、`ended_at` の無いブロックが1つも無いことを
確認する。** 走っていれば、その `review_at` まで新しい介入を出さない。同時に2つ
走ると、どちらが効いたか永久に分からない。

出せるのは1レビューに1つまで。`prediction`（何がどう動けば効いたと言えるか）と
`review_at` を書けないなら、それはまだ介入ではない。

**複数の習慣が同時に落ちているときは、個別の習慣に介入しない。** MO 水準の問題
として `targets` を空で立てる。ここを取り違えると、行動ごとに介入を打ち続けて
排他制約を4回破ることになる。

書くのは agent。実行するのは本人。

## Step 4: 対象の出し入れ

`config/habits.yaml` の `habits` に書いたもの**だけ**をレビューする。Habit と
Daily を区別せず名前で指定する。書いていないものは「対象外」に名前だけ出る
（Habitica からは消さない）。

`track` は Habit のときだけ書く（`up` / `down`）。**Habitica の up/down フラグ
ではなくこちらが正。** Daily には向きが無いので書かない。

**Habitica の Daily は「週x回」を表現できない**（`frequency` は曜日か `everyX`
のみ）。repeat を全曜日にして毎日 due にし、週何回かは `target_per_week` で持つ。
曜日固定にすると動けない日に未達が確定して融通が利かない。代わりに、目標が週7未満
の Daily は**目標日数を超えた分だけ毎週 HP を削られる**。difficulty を Trivial に
落とすと軽くできる（`docs/habitica.md` のとおり、agent は提案だけで変更しない）。

対象を増やしたい／減らしたいという話が出たら、実測を根拠にする。全期間の押下日と
最終押下日は history.csv から出る:

```bash
awk -F, 'NR>1 && $4=="habit" && ($9+0>0 || $10+0>0){print $1,$5}' data/habitica/history.csv
```

## Step 5: 目標値の見直し

`target_per_week` は本人が決める。**agent が実測から勝手に埋めない。**

4週ぶんの記録がそろってから、目標と実績が離れている習慣があれば提示する。
上げるか下げるか続けるかは本人が決め、合意が取れたら yaml を書き換える。

変更は git に残るので、いつ何から何へ変えたかが履歴になる。

**phase は凍結中。移行を提示しない。** 判定規則を決めていない（`docs/habits.md`）。
`habits.yaml` の `phase` は全習慣 `acquisition` のままで、触らない。

介入するかどうかは段を経由せず `clear` から直接決める（クリアできていない習慣が対象）。

## Step 6: 卒業と復帰

卒業させるときの Habitica 側の操作は2つ。**両方やる。**

1. `repeat` を全曜日 `false` にする（due にならなくなる）
2. Tag「卒業」を付ける

2 を忘れると「なぜ due でないのか」が後から分からない。**除外の条件は Tag だけ。**

卒業候補の自動提示は無い（`graduate.value_min` はどこからも読まれていない）。
`docs/habits.md` のとおり、維持期からの卒業は当面判定しないので、**卒業させるのは
本人の申告による**。

**卒業すると `value` が凍結するので、自動での復帰判定は働かない。** 崩れたことは
機械では検出できない。戻すのは本人の申告による。
